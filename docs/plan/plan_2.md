# Этап 1 — воспроизводимая задача прогнозирования гриппа

**Статус:** Этап 1 завершён; задача и baseline реализованы, интерфейс зафиксирован для следующих этапов.

## Постановка

- **Ряд:** число недельных госпитализаций с подтверждённым гриппом в США, FluSight «wk inc flu hosp», location=US.
- **Прогноз:** одно конечное неотрицательное число на горизонт 1; целевая суббота следует через семь дней после reference date. Это исследовательский точечный формат, не формат официальной вероятностной заявки FluSight.
- **Метрика:** MAE по всем датам validation. Прогнозы не округляются и не обрезаются.
- **Baseline:** последнее опубликованное к дате выпуска недельное число госпитализаций.
- **Допустимые библиотеки исполняемой программы:** стандартная библиотека Python и пакеты образа nir-stage0-executor:latest (NumPy, pandas, scikit-learn, SciPy, statsmodels, XGBoost, LightGBM и библиотеки графиков).

Правила горизонта и даты подачи взяты из [FluSight](https://github.com/cdcepi/FluSight-forecast-hub/blob/main/README.md); описание исторических версий — из [target-data README](https://github.com/cdcepi/FluSight-forecast-hub/blob/main/target-data/README.md).

## Данные и временные границы

Исходный target-data/time-series.csv закреплён на коммите d03574028ece110013c6284d3012ac4bef03ded7. В репозитории хранится только отфильтрованная выборка США: 16 875 строк, 102 версии as_of, 452 815 байт. Исходная выгрузка размером 95 МБ не хранится. Контрольные суммы, URL и лицензия указаны в data/stage1/provenance.json; текст лицензии приложен к данным.

В исходнике обнаружено 225 точных повторов пары (as_of, target_end_date) по выбранному ряду. Все значения внутри повторов совпали. Подготовка удаляет только идентичные повторы и учитывает их число в provenance; расходящиеся значения приводят к ошибке.

Для as_of раньше 2025-07-05 дата доступности равна as_of минус три дня: тогда as_of обозначало субботнюю reference date выпуска. Для более поздних версий as_of уже является датой публикации. На каждой дате выпуска выбирается **одна последняя доступная версия целиком**, без смешения значений из разных выпусков. История начинается с 2022-10-01 и расширяется по мере публикации новых наблюдений; прогнозируемая неделя никогда не входит во вход программы.

| Часть | Целевые субботы | Недель |
|---|---|---:|
| Validation | 2024-10-05 — 2025-05-31 | 35 |
| Отложенный test | 2025-10-04 — 2026-05-30 | 35 |

Для каждой целевой субботы reference date — предыдущая суббота, дата выпуска — среда перед ней. Истина для оценки хранится у evaluator и берётся из последней версии закреплённой выгрузки. Test-набор проверен по составу и доступной истории, но **test MAE не вычисляется до Этапа 4**.

## Контракт программы и оценка

Каждая неделя запускается в отдельном Docker-контейнере без сети и секретов. В workspace программы доступны:

- input/history.csv: колонки date,admissions, только известные на дату выпуска значения;
- input/task.json: issue_date, reference_date, target_end_date.

Программа записывает working/prediction.json с одним полем prediction и конечным неотрицательным числом. Ошибка запуска или неверный ответ отмечаются для конкретной недели; весь кандидат получает статус ERROR и не получает MAE, если хотя бы одна validation-неделя завершилась неуспешно. В последующих этапах такой кандидат расходует одну попытку поиска.

Управляющий процесс сохраняет для каждой недели дату, выбранную версию данных, прогноз, абсолютную ошибку, время, статус и stdout/stderr. Все программы, включая baseline, проходят через один evaluator и тот же Docker-executor Этапа 0.

## Воспроизведение и результат

~~~bash
./scripts/stage0/bootstrap.sh
./scripts/stage0/run_offline.sh
./scripts/stage1/prepare.sh
.venvs/aide/bin/python -m pytest tests/stage1
.venvs/aide/bin/python -m nir_stage1.evaluate --inspect-test
./scripts/stage1/run_validation.sh
~~~

Произвольную программу можно проверить командой ./scripts/stage1/run_validation.sh path/to/model.py. Отчёты и временные workspace сохраняются в игнорируемом artifacts/stage1/validation/.

**Baseline:** 35 из 35 недель успешно, MAE = 6332.714285714285. Это исходная контрольная точка, а не оценка качества будущих поисковых политик. В начале осеннего validation-периода последняя архивная версия может относиться к весне: FluSight публикует версии сезонно, поэтому baseline иногда использует старое последнее наблюдение.

Дальше на этом фиксированном интерфейсе можно генерировать кандидатов и сохранять деревья для сравнения Random, Greedy, ε-greedy и FUTS/PUCT. Отложенный test следует открывать только после завершения выбора политик и программ.
