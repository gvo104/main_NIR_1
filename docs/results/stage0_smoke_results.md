Reasoning можно отключить значением `reasoning_effort = "none"`. В `.env` остаются только `lite_llm_token` и `server_address`; их значения в отчёт и артефакты не записываются.

## Результат live AIDE

Создано два узла с корректной связью `parent → child`:

1. Первый узел успешно выполнился в Docker, обучил LightGBM и получил validation RMSE `29699.6111`. На его основе сохранён `best_solution.py`.
2. Второй узел продолжил первый, но завершился с `ContainerExecutionError` из-за некорректного callback LightGBM. Код, stdout/stderr и feedback с объяснением причины сохранены в `journal.json`.

Ошибочный второй узел не делает проверку частичной: по правилам исследования неисполняемые кандидаты расходуют попытку и должны сохраняться вместе с классифицированной ошибкой. Сквозной контракт `генерация → исполнение → оценка → сохранение` подтверждён первым узлом.

Для hosted vLLM локальный адаптер добавляет нейтральное user-сообщение к system-only запросам upstream AIDE. Каждый live-прогон получает уникальный workspace. Ответ без финального `content` после reasoning классифицируется отдельно как `reasoning_budget_exhausted`. Код подмодуля AIDE не изменялся.

## Безопасность исполнения

Сгенерированный код выполняется отдельным Docker-executor со следующими ограничениями:

- `--network none`;
- непривилегированный пользователь `1000:1000`;
- `--cap-drop ALL` и `no-new-privileges`;
- read-only root filesystem;
- единственный writable bind mount — workspace задачи; `/tmp` выделен как ограниченный tmpfs;
- 2 CPU, 4 GB RAM, 256 процессов и timeout 120 секунд;
- токен LLM и переменные OpenAI в контейнер не передаются.

Образ содержит NumPy, pandas, scikit-learn, SciPy, statsmodels, XGBoost, LightGBM и `libgomp1`. Проверены нормальное завершение, ненулевой exit code, timeout, отсутствие сети и секретов.

## Решение по итогам Этапа 0

Для следующих этапов принято:

- использовать AIDE как контур генерации, исполнения, feedback и журналирования;
- использовать ERA/FUTS как эталон алгоритма поиска и источник проверенной реализации PUCT;
- основное сравнение Random, Greedy, ε-greedy и FUTS/PUCT проводить на контролируемых фиксированных деревьях;
- не интегрировать FUTS непосредственно в AIDE до появления необходимости в online-эксперименте.

## Ограничения результата

- Проверена только одна реально доступная модель `qwen3.8-27b`; этого достаточно для Этапа 0, но не для сравнения генераторов.
- Качество LLM и качество прогноза не оценивались как исследовательский результат; проверялась техническая целостность контура.
- Endpoint не предоставил отдельный денежный cost или пригодную для отчёта полную статистику токенов.
- Визуализатор AIDE выдаёт не блокирующее предупреждение при нормализации координат дерева из двух узлов; журнал и HTML создаются корректно.
- FUTS не интегрирован в AIDE: на Этапе 0 подтверждена только возможность заменить выбор родителя.
- AIRA и FluSight намеренно отложены до следующих этапов согласно плану.
